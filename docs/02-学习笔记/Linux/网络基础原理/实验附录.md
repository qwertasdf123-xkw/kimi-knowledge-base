## §1 实验环境准备：eNSP + 设备清单

### 1.1 eNSP 是什么

**eNSP（Enterprise Network Simulation Platform）** = 华为官方推出的**网络仿真平台**，可在 Windows 上模拟 AR 路由器、S5700 交换机、AP、PC、Server 等设备，**零硬件**做实验。

### 1.2 实验设备清单（PDF 隐含）

| 设备 | 型号 | 数量 | 用途 |
|---|---|---|---|
| 路由器 | AR2220 / AR1220 | 1 | 跨网段互联 |
| 交换机 | S3700 / S5700 | 1-2 | 终端接入 |
| 终端 PC | PC | 1 | 用户主机 |
| 终端 Client | Client | 1 | 另一种终端（仅显示用） |
| 服务器 | Server（带 FTP/Web） | 2 | 提供 FTP / Web 服务 |
| 链路 | Copper / Serial | 若干 | 设备互联 |

> **PDF 实际配的**：1×Router + 1×SW + 1×Client1 + 1×PC1 + 1×FTP Server + 1×Web Server，**全部在 192.168.1.0/24 网段**。
>
> **PDF 关键提示**：路由器 G0/0/2 配的是 `192.168.2.254/24`（PDF §4.4）—— 说明 PDF **默认有 2 个子网**通过路由器互联。

### 1.3 IP 地址规划（PDF 实际方案）

| 设备 | 接口 | IP 地址 | 子网掩码 | 网关 | 所属子网 |
|---|---|---|---|---|---|
| **AR1** | G0/0/1 | 192.168.1.254 | 255.255.255.0 | — | 192.168.1.0/24 |
| **AR1** | G0/0/2 | 192.168.2.254 | 255.255.255.0 | — | 192.168.2.0/24 |
| **Client1** | eth0 | 192.168.1.10 | 255.255.255.0 | 192.168.1.254 | 192.168.1.0/24 |
| **PC1** | eth0 | 192.168.1.20 | 255.255.255.0 | 192.168.1.254 | 192.168.1.0/24 |
| **FTP Server** | eth0 | 192.168.1.30 | 255.255.255.0 | 192.168.1.254 | 192.168.1.0/24 |
| **Web Server** | eth0 | 192.168.1.40 | 255.255.255.0 | 192.168.1.254 | 192.168.1.0/24 |

> **规划原则**：路由器接口用 `.254`（网段内最大可用 IP），服务器/PC 用 `.10`/`.20`/`.30`/`.40`（方便记忆）。

### 1.4 拓扑连接

| 链路 | 设备 A | 设备 B | 线缆 |
|---|---|---|---|
| L1 | AR1 G0/0/1 | SW1 GE0/0/1 | Copper 直连 |
| L2 | Client1 eth0 | SW1 GE0/0/2 | Copper |
| L3 | PC1 eth0 | SW1 GE0/0/3 | Copper |
| L4 | FTP Server eth0 | SW1 GE0/0/4 | Copper |
| L5 | Web Server eth0 | SW1 GE0/0/5 | Copper |
| L6（可选） | AR1 G0/0/2 | SW2 GE0/0/1 | Copper |

## §2 实验 1：拓扑绘制与终端 IP 配置

### 2.1 实验目标

1. 打开 eNSP，熟悉工作区 / 设备栏 / 配置面板
2. 按 §1.4 表格绘制拓扑
3. 完成 Client1、PC1、FTP Server、Web Server 的 IP 配置
4. **保持所有链路 UP**（指示灯变绿）

### 2.2 步骤 1：绘制拓扑

```text
操作路径：
eNSP 主界面
  ├─ 工具栏：拖入设备
  │   ├─ "Router" 区 → 选 AR2220（拖 1 个到画布）
  │   ├─ "Switch" 区 → 选 S3700（拖 1 个到画布）
  │   ├─ "Terminal" 区 → 选 PC（拖 1 个）+ Client（拖 1 个）
  │   └─ "Server" 区 → 拖 2 个 Server
  ├─ 工具栏：选 Copper 线缆
  │   └─ 点击设备 A 端口 → 点击设备 B 端口 → 连线完成
  └─ 启动所有设备
      └─ 右键设备 → "启动" / 或工具栏"三角"按钮
```

**注意事项**：
- 启动后**等 30-60 秒**，等所有设备指示灯变绿
- 启动失败的设备**右键 → 删除 → 重新拖一个**（eNSP 启动失败是常态）

### 2.3 步骤 2：Client1 的 IP 配置

**eNSP 路径**：双击 Client1 → 弹出"Client1 配置"窗口 → "基础配置"标签。

```
IPv4 配置：
  ☑ 静态
  IP 地址:      192.168.1.10
  子网掩码:     255.255.255.0
  网关:         192.168.1.254
  DNS 服务器:   （留空或填 8.8.8.8）
```

> **Client1 在 eNSP 里没有 CLI**，只能在图形面板配 IP。**不能保存配置**（关掉就丢）。

### 2.4 步骤 3：PC1 的 IP 配置

**eNSP 路径**：双击 PC1 → "基础配置"标签。

```
IPv4 配置：
  ☑ 静态
  IP 地址:      192.168.1.20
  子网掩码:     255.255.255.0
  网关:         192.168.1.254
```

### 2.5 步骤 4（理论补充）：FTP / Web Server IP

**eNSP 路径**：双击 Server → "基础配置"标签。

```
FTP Server：
  IP 地址:      192.168.1.30
  子网掩码:     255.255.255.0
  网关:         192.168.1.254

Web Server：
  IP 地址:      192.168.1.40
  子网掩码:     255.255.255.0
  网关:         192.168.1.254
```

### 2.6 步骤 5：链路检查

```text
观察所有设备之间的连线：
  ✅ 链路正常 = 线缆两端接口指示灯都亮 + 路由器对应接口 PHY = up
  ❌ 链路断开 = 指示灯灭 / 路由器接口 PHY = down
```

**问题排查**：
- 线缆一端没插紧 → 重新点端口重连
- 设备未启动 → 等启动 / 重新启动
- 接口类型不匹配 → PC 用 Copper，路由器接口用 Copper

## §3 实验 2：FTP / Web 服务器配置

### 3.1 实验目标

eNSP 的 Server 设备**自带** FTP 和 Web 服务软件，**只需在图形面板"开启"** 即可。

### 3.2 步骤 1：配置 FTP Server

**eNSP 路径**：双击 FTP Server → **"服务器信息"** 标签 → 点击 `FtpServer` 选项。

| 配置项 | 操作 |
|---|---|
| **文件根目录** | 点击"选择文件夹"→ 选一个本地目录（如 `D:\ftp_share`） |
| **用户名**（可选） | 默认空（匿名访问） |
| **密码**（可选） | 默认空 |
| **启动服务** | 点击"启动"按钮 |

**关键反馈**：

```
启动前："启动" 按钮高亮，"停止" 按钮灰色
启动后："启动" 按钮变灰色，"停止" 按钮高亮  ✅ 服务已起
```

> **匿名 FTP**：根目录 + 用户名密码都空着，客户端直接 `ftp 192.168.1.30` 就能登。

### 3.3 步骤 2：配置 Web Server

**eNSP 路径**：双击 Web Server → "服务器信息" 标签 → 点击 `HttpServer` 选项。

| 配置项 | 操作 |
|---|---|
| **网站根目录** | 点击"选择文件夹"→ 选一个含 `index.html` 的目录 |
| **端口** | 默认 80（可改 8080） |
| **启动服务** | 点击"启动"按钮 |

**最小网页测试**：

在网站根目录建 `index.html`：

```html
<!DOCTYPE html>
<html>
<head><meta charset="utf-8"><title>测试</title></head>
<body>
  <h1>Hello from Web Server 192.168.1.40</h1>
  <p>当前时间: <span id="t"></span></p>
  <script>document.getElementById('t').innerText = new Date().toLocaleString();</script>
</body>
</html>
```

> 启动 Web 服务后，从 PC1 浏览器访问 `http://192.168.1.40` 即可。

### 3.4 步骤 3：服务自检（在 Server 设备内）

**eNSP 路径**：双击 Server → "命令行" 标签（部分 Server 设备支持）。

```bash
# 自带 FTP 客户端测试
ftp 192.168.1.30
# 用户名 anonymous 或留空
# ls / get test.txt
```

## §4 实验 3：华为路由器接口配置

> **完整 PDF 原文摘录**（PDF §4.4），按出现顺序整理。

### 4.1 实验目标

通过 CLI（命令行）给 AR1 路由器的 G0/0/1 和 G0/0/2 配置 IP 地址，**让路由器能在两个子网间转发**。

### 4.2 完整命令清单（PDF 原文 + 注释）

#### 4.2.1 进入系统视图

```bash
<Huawei>                          # 默认用户视图（尖括号）
<Huawei>system-view
Enter system view, return user view with Ctrl+Z.
[Huawei]                          # 系统视图（方括号）
```

**两种视图区别**：
- `<Huawei>` **用户视图**：只能看（display 类命令），不能改配置
- `[Huawei]` **系统视图**：可以改全局配置
- `[Huawei-GigabitEthernet0/0/1]` **接口视图**：只改这一个接口

#### 4.2.2 tab 补全（PDF 强调）

```bash
# Huawei> dis<tab>   → 自动补全为 display
# [Huawei]dis<tab>   → 自动补全为 display
# [Huawei]display int<tab> → display interface
# [Huawei]display interface br<tab> → display interface brief
```

> **PDF 强调 tab 补全**：eNSP 里**真支持 tab**，多敲两下能少打很多字。

#### 4.2.3 查看接口状态（配 IP 之前）

```bash
[Huawei]display interface brief
```

**典型输出（PDF 原文）**：

```
PHY: Physical      *down: administratively down    ^down: standby
(l): loopback      (s): spoofing                   (b): BFD down
(e): ETHOAM down   (d): Dampening Suppressed
InUti/OutUti: input utility/output utility

Interface                    PHY    Protocol  InUti  OutUti  inErrors  outErrors
Ethernet0/0/0                down   down       0%      0%        0         0
Ethernet0/0/1                down   down       0%      0%        0         0
GigabitEthernet0/0/0         down   down       0%      0%        0         0
GigabitEthernet0/0/1         up     down       0%      0%        0         0
GigabitEthernet0/0/2         up     down       0%      0%        0         0
GigabitEthernet0/0/3         down   down       0%      0%        0         0
NULL0                        up     up(s)      0%      0%        0         0
Serial0/0/0                  down   down       0%      0%        0         0
Serial0/0/1                  down   down       0%      0%        0         0
Serial0/0/2                  down   down       0%      0%        0         0
Serial0/0/3                  down   down       0%      0%        0         0
```

**关键列含义（PDF 原文）**：

| 列 | 含义 |
|---|---|
| **PHY** | 物理层状态：up = 网线接好，down = 没接 |
| **Protocol** | 协议层状态：**有 IP = up，没 IP = down** |

> **所以 G0/0/1 物理 up 但 Protocol down，是因为还没配 IP**。配完 IP 后 Protocol 自动 up。

#### 4.2.4 给 G0/0/1 配 IP（PDF 原文）

```bash
[Huawei]interface G0/0/1
[Huawei-GigabitEthernet0/0/1]ip address 192.168.1.254 24
```

**24 = 子网掩码长度**（= 255.255.255.0），也支持 `255.255.255.0` 写法。

**提示信息（PDF 原文）**：

```
Oct 20 2025 09:27:43-08:00 Huawei %%01IFNET/4/LINK_STATE(l)[0]:The line protocol
 IP on the interface GigabitEthernet0/0/1 has entered the UP state.
Oct 20 2025 09:27:43-08:00 Huawei DS/4/DATASYNC_CFGCHANGE:OID
1.3.6.1.4.1.2011.5.25.191.3.1 configurations have been changed. ...
```

> **这些是日志**，说"接口协议状态变 UP 了" + "配置变更已记录"。

#### 4.2.5 配完后再次查看接口状态

```bash
[Huawei-GigabitEthernet0/0/1]display interface brief
```

**预期输出（PDF 原文）**：

```
...
GigabitEthernet0/0/1         up     up        0%      0%        0         0  ← Protocol 变 up
...
```

> **PHY up + Protocol up = 这接口可以工作了**。

#### 4.2.6 给 G0/0/2 配 IP（PDF 原文）

```bash
[Huawei-GigabitEthernet0/0/1]interface G0/0/2
[Huawei-GigabitEthernet0/0/2]ip address 192.168.2.254 24
[Huawei-GigabitEthernet0/0/2]
Oct 20 2025 09:29:02-08:00 Huawei %%01IFNET/4/LINK_STATE(l)[1]:The line protocol
 IP on the interface GigabitEthernet0/0/2 has entered the UP state.
[Huawei-GigabitEthernet0/0/2]quit
```

```bash
[Huawei]undo info-center enable
Info: Information center is disabled.
```

> **关掉日志**：实验时日志刷屏很烦，`undo info-center enable` 一键关。

## §5 实验 4：连通性与服务验证

### 5.1 实验目标

1. 验证 PC1 能 ping 通所有设备（同子网 + 跨子网）
2. 验证 PC1 能访问 FTP Server
3. 验证 PC1 能访问 Web Server

### 5.2 验证 1：网络连通性（PDF §4.5.1）

**路径**：双击 PC1 → "命令行" 标签。

```bash
# 测同子网网关
PC>ping 192.168.1.254
# 预期：5 个包都通，time < 10ms

# 测同子网 FTP Server
PC>ping 192.168.1.30

# 测同子网 Web Server
PC>ping 192.168.1.40

# 测跨子网网关
PC>ping 192.168.2.254

# 测跨子网客户端（如果有）
PC>ping 192.168.2.10
```

**预期结果分析**：

| 目标 | 同子网？ | 走路由器？ | 预期 |
|---|---|---|---|
| `192.168.1.254` | 同 | 不走 | 通 |
| `192.168.1.30/40` | 同 | 不走 | 通（走交换机） |
| `192.168.2.254` | 跨 | 走 G0/0/1 → G0/0/2 | 通 |
| `192.168.2.10` | 跨 | 走 G0/0/1 → G0/0/2 → SW2 | 通 |

**连通性逐层诊断（自底向上）**：

```
ping 不通？
  │
  ├─ step1: 链路层  → 看网线指示灯、display interface brief 看 PHY
  │            └─ PHY down = 换网线 / 查物理
  │
  ├─ step2: 本机   → ipconfig 看本机 IP / 掩码 / 网关
  │            └─ IP 不对 = 改 IPv4 配置
  │
  ├─ step3: 同网段  → ping 网关
  │            └─ 网关不通 = 路由器接口没配 IP / 接口关闭
  │
  └─ step4: 跨网段  → ping 跨子网
               └─ 不通 = 没配路由（默认直连子网能通，跨子网需路由表）
```

## §6 易错点 ×10（实验特有问题）

> 下面这些坑，**理论章节不会出现**，只有真上手 eNSP 才会踩到。

1. **eNSP 设备启动失败** → 右键删除 → 重新拖一个（VirtualBox 残留导致）
2. **链路指示灯不亮** → 检查线缆类型（PC 用 Copper，串口用 Serial）+ 检查端口是否接对
3. **路由器 G0/0/1 PHY up 但 Protocol down** → **没配 IP**（这是正常的，配完 IP 就 up）
4. **配完 IP 忘 save** → 关闭 eNSP 后下次启动配置全丢（**eNSP 模拟器尤其明显**）
5. **FTP "Connection refused"** → **90% 是服务没点"启动"按钮**（很多新人配完 IP 就走，没点启动）
6. **Web 报 404** → 网站根目录没 `index.html`（FTP 同理，没文件就 ls 不到）
7. **PC 浏览器输 IP 错** → 写 `192.168.1.40:80` 可以，**不要写** `http:\\192.168.1.40`（反斜杠）
8. **跨子网 ping 不通** → 默认路由器**不转发流量**，需配路由（直连网段会**自动**加路由表，所以本实验能通）
9. **undo info-center enable 没敲** → 日志刷屏干扰实验，**强烈建议**一开始就关
10. **PC1 的网关忘填** → 同子网能通，跨子网直接断（网关空 = 不知道往哪发包）

## §8 面试 6 大追问：实验角度

1. **eNSP 启动设备失败怎么办？**
   - 原因：VirtualBox 后台残留 / WinPcap 没装 / 系统兼容性
   - 处理：右键删除失败设备 → 重拖 → 重启 eNSP → 必要时重启电脑
   - 真机操作：检查物理链路（网线 / 光模块 / 串口线）

2. **PHY up + Protocol up 是什么意思？分别在哪一层？**
   - PHY = **物理层** up（网线接好、信号通）
   - Protocol = **数据链路层** up（接口有 IP，链路协议正常工作）
   - **两层都 up = 接口真正能用**；只有 PHY up = 物理通但协议没起

3. **路由器 G0/0/1 和 G0/0/2 配完 IP 后，默认能不能跨子网转发？**
   - **能**（直连路由自动出现）
   - 直连路由 = 接口 IP 配好后**自动**进入路由表，`Pre=0, Cost=0`
   - 不需要手动配静态路由，**前提是两端都配了 IP**

4. **FTP 和 Web 服务的默认端口分别是？**
   - FTP：**21（控制）** + 20（数据）
   - Web（HTTP）：**80**
   - HTTPS：443
   - 记忆：**"FTP 21-20" "HTTP 80"** —— 数字大小和服务年代正相关

5. **服务器没启动 / 网关忘配 / 根目录错，分别会出什么错？**
   - 服务没启动 → `Connection refused`（TCP 握手 RST）
   - 网关忘配 → 同子网通，跨子网全断（不知道往哪发包）
   - 根目录错 → FTP 看不到文件 / Web 404

6. **eNSP 里 PC 的网关忘配，会发生什么？怎么验证？**
   - **同子网能 ping 通**（直接走交换机，ARP 解析 MAC）
   - **跨子网全 ping 不通**（PC 不知道包该交给谁，直接丢弃）
   - 验证：`PC>ping 192.168.2.254` → "Destination host unreachable"
   - 解决：双击 PC → 基础配置 → 填网关 `192.168.1.254`
