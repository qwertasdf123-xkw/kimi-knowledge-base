## §0 心智模型：网络 = 一座城市的交通系统

把计算机网络想象成 **一座城市的交通系统**：

| 网络概念 | 城市比喻 | 实际 |
|---|---|---|
| 数据包（packet） | 一辆辆小汽车 | 携带信息的小数据块 |
| 网卡（NIC） | 每栋房子的车库 | 数据进出网络的接口 |
| 交换机（Switch） | 路口红绿灯 | 让相邻几栋楼互通 |
| 路由器（Router） | 城市间的高速公路收费站 | 连接不同网络 |
| IP 地址 | 房子的"门牌号" | 网络层定位 |
| MAC 地址 | 房子的"产权证号" | 数据链路层定位 |
| 子网掩码 | 城市的"行政区划" | 划分网络范围 |
| 网关（Gateway） | 出城收费站 | 不同子网间的出口 |
| 防火墙（Firewall） | 城市的公安检查站 | 控制进出流量 |
| 协议（Protocol） | 交通法规 | 数据传输规则 |
| 端口（Port） | 房子里的"房间号" | 应用层定位 |
| DNS | 城市的"门牌查询 114" | 域名 → IP 转换 |

### 关键洞察

> **"网络的核心功能不是传输数据，而是让分散的资源能**够**互相访问"** —— 网络 = 节点 + 连接 + 规则。

### 网络全景图

```
┌──────────────────────────────────────────┐
│              互联网 (Internet)             │  ← 公网
│  ┌────────────┐    ┌────────────┐         │
│  │  路由器 R1  │────│  路由器 R2  │        │
│  └─────┬──────┘    └──────┬─────┘         │
│        │                  │               │
│  ┌─────┴──────┐     ┌─────┴──────┐       │  ← 不同子网
│  │   子网A    │     │   子网B    │         │
│  │ 192.168.1.0│     │192.168.2.0 │         │
│  │ ┌──────┐  │     │ ┌──────┐  │         │
│  │ │ SW1  │  │     │ │ SW2  │  │         │  ← 交换机
│  │ └─┬──┬─┘  │     │ └─┬──┬─┘  │         │
│  │   PC1 PC2  │     │   PC3 PC4  │         │  ← 终端
│  └────────────┘     └────────────┘         │
└──────────────────────────────────────────┘
```

### 💬 回答你的疑问

> **Q1：网络和互联网的区别？**

**A**：
- **网络（Network）**：通用概念，泛指任何互联的设备集合（你家的 wifi 也是一个网络）。
- **互联网（Internet）**：全球最大的**网络的网络**，所有公网互通。

> **Q2：路由器和交换机的本质区别？**

**A**：
- **交换机**（Layer 2）：靠 **MAC 地址** 工作，连同一网络内的设备，转发快。
- **路由器**（Layer 3）：靠 **IP 地址** 工作，连**不同**网络，路径选择。

> **Q3：为什么有 MAC 还要 IP 地址？**

**A**：层级化设计：
- **MAC 地址**是"网卡身份证"（厂家烧录，全球唯一，但**不告诉你位置**）
- **IP 地址**是"门牌号"（按网络划分，能**寻址路由**）
- 用 IP 找到目标网络 → 用 MAC 找到具体设备（ARP 完成这个转换）

## §1 网络初探：是什么/设备/分类（PDF 01）

> **来源**：PDF 01 网络初探-认识网络（4 页）。

### 1.1 网络的定义

> **"将地理位置不同、具有独立功能的多台计算机及其外部设备，通过通信线路和通信设备连接起来，在一系列规则的管理下，实现资源共享和信息传递的系统。"**

### 1.2 网络的核心功能

| 功能 | 含义 | 例子 |
|---|---|---|
| **资源共享** | 共享硬件/软件/数据 | 大家共用打印机、共享文件 |
| **数据通信** | 互相传递信息 | 邮件、微信、视频通话 |
| **分布式处理** | 多台机器并行算 | 大数据计算分片 |
| **提高可靠性** | 多路径备份 | 一条线断了换另一条 |

### 1.3 网络设备

| 设备 | 工作层级 | 作用 | 关键词 |
|---|---|---|---|
| **交换机**（Switch） | Layer 2 | 终端接入 + 帧交换 | "最近用户的设备" |
| **路由器**（Router） | Layer 3 | 跨网络转发 + 路径选择 | "按目的地址选路" |
| **防火墙**（Firewall） | 多层 | 网络安全隔离 | "监测 / 限制 / 屏蔽" |
| **无线设备**（AP / 无线控制器） | Layer 2/3 | 提供 wifi 接入 | 移动设备入网 |
| **集线器**（Hub，已淘汰） | Layer 1 | 物理层信号放大 | 现在都用交换机替代 |

### 1.4 网络分类（按地理范围）

| 类型 | 英文 | 范围 | 速度 | 例子 |
|---|---|---|---|---|
| **局域网** | LAN | 房间 / 楼宇 / 校园 | 100Mbps - 10Gbps | 家庭 wifi、办公室网 |
| **城域网** | MAN | 整个城市 | 1Gbps - 100Gbps | 城市有线电视网、政府专网 |
| **广域网** | WAN | 国家 / 跨国家 | 1Mbps - 1Gbps | 互联网、运营商骨干网 |
| **互联网** | Internet | 全球 | 差异大 | 全球互联 |

### 1.5 网络分类（其他维度）

| 维度 | 分类 | 含义 |
|---|---|---|
| **拓扑** | 总线型 / 星型 / 环型 / 网状 | 节点连接形状 |
| **介质** | 有线 / 无线 | 传输媒介 |
| **使用者** | 公网 / 私网 | 是否对外 |
| **OSI 范围** | LAN / WAN / Internet | 地理范围 |

### 1.6 现代网络以"交换 + 路由"为核心

```
[PC] ←→ [交换机] ←→ [路由器] ←→ [Internet]
                                 ↘
                              [其他网络]
```

### 易错点

- ❌ 把"互联网"等同于"网络" → 互联网只是全球最大的网络
- ❌ 把"集线器（Hub）"当成"交换机（Switch）" → Hub 是物理层设备，所有端口共享带宽；Switch 是数据链路层，每个端口独立带宽
- ❌ 把"局域网"想成"内部网络"→ 内网更多是"私网/受限"的概念

## §2 网络参考模型：OSI 7 层 + TCP/IP 4 层

> **来源**：PDF 03 网络参考模型（11 页）。这是网络的**理论骨架**。

### 2.1 为什么需要分层？

**类比**：邮寄一个包裹
- 你写好收件人地址（应用层关心）
- 快递员打包（传输层关心）
- 包裹装车（网络层关心）
- 司机上路（数据链路层关心）
- 物理道路（物理层关心）

**每一层只关心自己的工作**，互不干扰。

### 2.2 OSI 7 层模型（理论）

| 层   | 名称        | 数据单位       | 关键设备 / 协议              | 关键概念      |
| --- | --------- | ---------- | ---------------------- | --------- |
| 7   | **应用层**   | 数据（Data）   | HTTP / FTP / DNS / SSH | 用户接口      |
| 6   | **表示层**   | 数据         | SSL/TLS / JPEG / ASCII | 编码、加密、压缩  |
| 5   | **会话层**   | 数据         | RPC / NetBIOS          | 会话管理、同步   |
| 4   | **传输层**   | 段（Segment） | TCP / UDP              | 端到端、端口、可靠 |
| 3   | **网络层**   | 包（Packet）  | IP / ICMP / OSPF / 路由器 | 路由、寻址     |
| 2   | **数据链路层** | 帧（Frame）   | Ethernet / PPP / 交换机   | MAC、差错检测  |
| 1   | **物理层**   | 位（Bit）     | 网线 / 光纤 / Hub          | 电压、机械、时序  |

> **记忆口诀**（从下往上）：**"物数网传会表应"**（物理、数据链路、网络、传输、会话、表示、应用）

### 2.3 TCP/IP 4 层模型（实际）

OSI 是理论模型，实际用的**TCP/IP 模型**只有 4 层：

| TCP/IP 层 | 对应 OSI | 关键协议 |
|---|---|---|
| **应用层** | 5+6+7（会话+表示+应用） | HTTP / FTP / DNS / SSH / SMTP |
| **传输层** | 4 | TCP / UDP |
| **网络层**（网际层） | 3 | IP / ICMP / ARP / IGMP |
| **网络接口层**（链路层+物理层） | 1+2 | Ethernet / MAC / 网线 |

### 2.4 数据封装与解封装（核心流程）

```
发送方（自上而下封装）：
应用层：HTTP 请求 [Data]
  ↓ 加 TCP 头
传输层：TCP 头 + Data [Segment]
  ↓ 加 IP 头
网络层：IP 头 + TCP 头 + Data [Packet]
  ↓ 加 MAC 头/尾
链路层：MAC 头 + IP+TCP+Data + MAC 尾 [Frame]
  ↓ 转为电信号
物理层：电信号 [Bit]

接收方（自下而上解封装）：反过来
```

### 2.5 OSI 与 TCP/IP 对照图

```
        OSI 7层                  TCP/IP 4层
        ┌─────────┐
应用层 ←→│  应用    │←─ HTTP/FTP/DNS
表示层 ←→│  表示    │  ←合并→
会话层 ←→│  会话    │         应用层
        ├─────────┤
传输层 ←→│  传输    │←─ TCP/UDP
        ├─────────┤
网络层 ←→│  网络    │←─ IP/ICMP/ARP     网络层
        ├─────────┤
链路层 ←→│  链路    │←─ MAC/Ethernet
物理层 ←→│  物理    │  ←合并→           网络接口层
        └─────────┘
```

### 2.6 各层典型的"问候语"

```
应用层 ：HTTP GET / → "您好，请给我数据"
传输层 ：TCP = "我保证送到"      UDP = "我尽力送"
网络层 ：IP = "发到 192.168.1.1"
链路层 ：MAC = "发到 xx:xx:xx:xx:xx:xx"
物理层 ：电压 = "010101000101..."
```

### 2.7 各层常见故障

| 层 | 故障现象 | 排查工具 |
|---|---|---|
| 物理层 | 网线不通、指示灯不亮 | 换网线、看指示灯 |
| 链路层 | MAC 冲突、广播风暴 | 交换机端口、wireshark |
| 网络层 | ping 不通、traceroute 断 | `ping`, `traceroute` |
| 传输层 | 端口未开、连接超时 | `telnet`, `nc` |
| 应用层 | 404 / 500 / 登录失败 | 浏览器、curl |

### 易错点

- ❌ 拿 OSI 模型去查实际问题 → 实际用 TCP/IP 4 层
- ❌ "物理层"以为是物理设备 → 是"信号"（电/光/射频）
- ❌ 路由器只在网络层工作 → 现代路由器是**多层设备**，还会做 NAT、防火墙等

## §3 IPv4 编址：分类/子网掩码/CIDR（PDF 04）

> **来源**：PDF 04 网络层协议及 IP 编址（7 页）。

### 3.1 IP 地址的格式

**IPv4** = 32 位 = 4 个字节 = 4 段点分十进制

```
192.168.1.1
   ↑   ↑  ↑  ↑
  第1 第2 第3 第4 段（每段 8 bit / 1 字节）
  范围：0 - 255
```

**总地址空间**：2^32 = 4,294,967,296 ≈ 43 亿个（已不够分）。

### 3.2 IP 地址分类（A/B/C/D/E）

| 类别      | 第 1 段范围 | 默认子网掩码              | 网络号位数 | 主机号位数 | 最大主机数      | 用途   |
| ------- | ------- | ------------------- | ----- | ----- | ---------- | ---- |
| **A 类** | 1-126   | 255.0.0.0 (/8)      | 8     | 24    | 16,777,214 | 大型网络 |
| **B 类** | 128-191 | 255.255.0.0 (/16)   | 16    | 16    | 65,534     | 中型网络 |
| **C 类** | 192-223 | 255.255.255.0 (/24) | 24    | 8     | 254        | 小型网络 |
| **D 类** | 224-239 | —                   | —     | —     | —          | 组播   |
| **E 类** | 240-255 | —                   | —     | —     | —          | 实验   |

**特殊 IP**：
- **127.0.0.1**：回环地址（自己）= localhost
- **0.0.0.0**：所有 IP / 未分配
- **255.255.255.255**：全网广播

### 3.3 私有 IP 段（NAT 后）

| 段 | 范围 | 子网掩码 | CIDR |
|---|---|---|---|
| **10.0.0.0/8** | 10.0.0.0 - 10.255.255.255 | 255.0.0.0 | /8 |
| **172.16.0.0/12** | 172.16.0.0 - 172.31.255.255 | 255.240.0.0 | /12 |
| **192.168.0.0/16** | 192.168.0.0 - 192.168.255.255 | 255.255.0.0 | /16 |

> **你的家庭 wifi 多半是 192.168.x.x / 24 或 192.168.x.x / 16**。

### 3.4 子网掩码

**作用**：区分 IP 地址中的"网络号"和"主机号"。

```
IP 地址：   192.168.1.100
子网掩码：  255.255.255.0
二进制位：  11111111.11111111.11111111.00000000
                          ↑              ↑
                     网络号（24 位）   主机号（8 位）
```

**逻辑**：
- IP 与 子网掩码 **AND** = 网络号
- 同网络号的设备互相直接通信（不需路由器）

**示例计算**：
```
192.168.1.100 AND 255.255.255.0 = 192.168.1.0  ← 网络号
192.168.1.100 AND 0.0.0.255     = 0.0.0.100     ← 主机号
```

### 3.5 CIDR（无类域间路由）

**CIDR = Classless Inter-Domain Routing**，用斜线表示网络位数：

```
192.168.1.100/24    ← 网络号 24 位
10.1.0.0/8          ← 8 位
172.16.50.0/22      ← 22 位（B 类子网划小）
```

**优势**：打破 A/B/C 类固定大小，**按需划分**。

### 3.6 VLSM（可变长子网掩码）

**VLSM = Variable Length Subnet Masking**，子网掩码可以长短不一。

**例**：用 192.168.1.0/24 划成两个 /25：
- 192.168.1.0/25（126 台主机）
- 192.168.1.128/25（126 台主机）

或者划成 1 个 /26 + 2 个 /27：
- 192.168.1.0/26（62 台）
- 192.168.1.64/27（30 台）
- 192.168.1.96/27（30 台）

### 3.7 子网划分实战

**目标**：把 192.168.1.0/24 划成 4 个子网，每个 60 台主机。

**步骤**：
```
需要主机数：60+2（网络号+广播）= 62 → 需 6 位主机号
2^6 = 64 ≥ 62 ✓
→ 子网掩码 = /26（= 255.255.255.192）

子网 1：192.168.1.0/26   （0-63）
子网 2：192.168.1.64/26  （64-127）
子网 3：192.168.1.128/26 （128-191）
子网 4：192.168.1.192/26 （192-255）
```

### 3.8 速算：子网主机数

```
可用主机数 = 2^(32 - 网络位数) - 2
（-2 是扣掉网络号 + 广播地址）
```

| CIDR | 子网掩码            | 主机数    |
| ---- | --------------- | ------ |
| /24  | 255.255.255.0   | 254    |
| /25  | 255.255.255.128 | 126    |
| /26  | 255.255.255.192 | 62     |
| /27  | 255.255.255.224 | 30     |
| /28  | 255.255.255.240 | 14     |
| /29  | 255.255.255.248 | 6      |
| /30  | 255.255.255.252 | 2      |
| /32  | 255.255.255.255 | 1（单主机） |

### 3.9 网络号 vs 主机号 vs 广播地址（每子网 3 个特殊地址）

```
子网 192.168.1.0/26：
  网络地址（最小）：192.168.1.0    ← 不能用作主机
  主机范围：        192.168.1.1 ~ 192.168.1.62  ← 可用
  广播地址（最大）：192.168.1.63   ← 不能用作主机
```

### 3.10 子网划分的 5 个步骤

```
1. 确定需要的子网数（或最大子网的大小）
2. 计算所需的主机位数（2^h ≥ 主机数）
3. 确定新子网掩码（/32 - h 位）
4. 划分子网（从 0 开始按位块算）
5. 列出每个子网的：网络地址 + 主机范围 + 广播地址
```

### 易错点

- ❌ 忘了 -2（网络号 + 广播）就分配 → 第一个 / 最后一个主机 IP 用不了
- ❌ 跨子网通信默认不能直接发 → 需要路由器
- ❌ 把"私有 IP"和"公网 IP"搞混 → 私有 IP 在 NAT 后面，公网 IP 全球唯一
- ❌ 以为 /32 是广播 → /32 是单主机（255.255.255.255 才是广播）

## §4 IPv6 简述（PDF 04）

### 4.1 IPv6 的核心：128 位地址

**IPv4** 的问题：43 亿地址已经耗尽。

**IPv6** 用 **128 位** = 2^128 = 340 涧（10^38）地址。**地球每平方米分配 6.5×10^28 个**（足够给每粒沙子一个地址）。

### 4.2 IPv6 的格式

**8 组 16 进制数**，每组 4 个 16 进制位（= 16 位）：

```
2001:0db8:0000:0000:0000:ff00:0042:8329
   ↑    ↑    ↑    ↑    ↑    ↑    ↑    ↑
  8组，每组16位（共128位）
```

### 4.3 简化写法

**规则**：每组**前导 0 可省**，**连续 0 组可用 `::`**（全文档只能一次）：

```
完整写法：   2001:0db8:0000:0000:0000:ff00:0042:8329
省略前导0：  2001:db8:0:0:0:ff00:42:8329
连续0简写：  2001:db8::ff00:42:8329
全0地址：    ::1（= 回环 localhost）
            ::（= 全 0）
```

### 4.4 IPv6 简化实战

```
原始：     FF02:0000:0000:0000:0000:0000:0000:0001
前导0省略：  FF02:0:0:0:0:0:0:1
连续0简写：  FF02::1
```

### 4.5 IPv4 vs IPv6 对比

| 维度 | IPv4 | IPv6 |
|---|---|---|
| 地址位数 | 32 位 | 128 位 |
| 地址数 | 43 亿 | 340 涧 |
| 表示法 | 点分十进制 | 冒号分 16 进制 |
| 头部 | 20-60 字节（可变） | **固定 40 字节** |
| 配置 | 手动 / DHCP | **自动（无状态）** |
| 安全性 | 需 IPSec | **原生 IPSec** |
| 路由 | 复杂 | 简化 |

### 4.6 IPv6 地址类型

| 类型 | 前缀 | 作用 |
|---|---|---|
| **单播**（Unicast） | — | 一对一 |
| **组播**（Multicast） | FF00::/8 | 一对多 |
| **任播**（Anycast） | — | 最近的一个接收 |

> **IPv6 没有广播**！广播全部用**组播**实现（FF02::1 = 所有节点，FF02::2 = 所有路由器）。

## §5 以太网基础（PDF 06）

> **来源**：PDF 06 以太网交换基础（13 页）。

### 5.1 以太网是啥

**以太网（Ethernet）** = 当前最主流的**局域网技术标准**。

```
IEEE 802.3 标准族 = 以太网
                ↓
        10Mbps / 100Mbps / 1Gbps / 10Gbps / 100Gbps
                ↓
       几乎所有局域网都是以太网
```

### 5.2 MAC 地址 = 网卡身份证

**MAC（Media Access Control）地址** = 48 位 = 6 字节 = 16 进制

```
00:1A:2B:3C:4D:5E
↑                ↑
厂商 OUI（24 位）  设备序列号（24 位）
```

**特点**：
- **全球唯一**（理论上）：前 24 位是 IEEE 分配的厂商代码，后 24 位是厂商自定序列号
- **烧录在网卡**（可软件修改，但改了不规范）
- **不可路由**（只用于局域网内寻址）
- **48 位**够全球 70 万亿设备

**查看 MAC**（Linux）：
```bash
ip link show
# 2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP>
#     link/ether 00:1a:2b:3c:4d:5e

ifconfig eth0
# eth0   Link encap:Ethernet  HWaddr 00:1A:2B:3C:4D:5E
```

### 5.3 CSMA/CD（载波监听多路访问 / 冲突检测）

**早期以太网（半双工）** 的工作机制：

```
1. 监听（Carrier Sense）：先听信道，空闲才发
2. 等待（Multiple Access）：空闲后等随机时间才发
3. 冲突检测（Collision Detection）：发的同时监听是否碰撞
4. 冲突后退避：碰撞后等随机时间再试
```

> **现在的全双工以太网不需要 CSMA/CD**（因为发送/接收各占一对线，不会冲突）。

### 5.4 全双工 vs 半双工

| 维度 | 半双工 | 全双工 |
|---|---|---|
| 同时收发 | ❌ 不能 | ✅ 可以 |
| CSMA/CD | 需要 | 不需要 |
| 速度 | 等于带宽 | **理论 2 倍** |
| 介质 | 一对线（Hub 接） | 两对线（Switch 接） |

### 5.5 以太网帧格式

```
┌────────┬────────┬──────────┬───────────┬──────┬───────────┬──────┐
│ 前导码  │ SFD    │ MAC 目标 │ MAC 源    │ 类型  │ Data+载荷  │ FCS  │
│ 7B     │ 1B    │ 6B      │ 6B       │ 2B   │ 46-1500B  │ 4B   │
└────────┴────────┴──────────┴───────────┴──────┴───────────┴──────┘
                                                    ↑
                                            最大 1500 字节（MTU）
```

**最小帧 = 64 字节**（含头尾），不足要补 padding。

### 5.6 以太网类型字段（Type）

```
0x0800 = IPv4
0x0806 = ARP
0x86DD = IPv6
0x8100 = VLAN 标签（4 字节）
```

### 易错点

- ❌ MAC 是 IP 的"另一种"地址 → MAC 是链路层用，IP 是网络层用，**配合工作**
- ❌ MAC 地址全球唯一是绝对保证 → 实际上**可能重复**（伪造或厂商没买 OUI）
- ❌ CSMA/CD 现在还要 → 全双工不需要，半双工基本淘汰

## §6 ARP 协议（PDF 06）

### 6.1 ARP 解决什么问题？

**网络层用 IP，链路层用 MAC**。**ARP = Address Resolution Protocol**，**IP → MAC** 转换协议。

```
PC1 知道 PC2 的 IP：192.168.1.100
PC1 需要 PC2 的 MAC 才能发帧
  ↓
ARP 流程：广播 "192.168.1.100 是谁？" → PC2 答 "我是 xx:xx:xx:xx:xx:xx"
```

### 6.2 ARP 工作流程

```
PC1: 192.168.1.10   MAC: AA:AA:AA:AA:AA:AA
PC2: 192.168.1.20   MAC: BB:BB:BB:BB:BB:BB

PC1 想发：IP 192.168.1.20
  ↓
PC1 查本地 ARP 缓存
  ├─ 有 → 直接用 MAC 发帧
  └─ 无 → 发 ARP 请求（广播）

ARP 请求（目的 MAC = FF:FF:FF:FF:FF:FF）：
"谁有 192.168.1.20？答 AA:AA:AA:AA:AA:AA"

全网接收 → PC2 看到自己 IP → 单播答：
"192.168.1.20 是 BB:BB:BB:BB:BB:BB"

PC1 收到 → 缓存（IP+MAC）→ 发真正的帧
```

### 6.3 ARP 缓存（ARP Cache）

**存储**：IP ↔ MAC 映射表，**有时效**（Linux 默认 60s 可调）。

```bash
# Linux 查看 ARP 缓存
ip neigh show
arp -a

# 添加静态 ARP
arp -s 192.168.1.20 BB:BB:BB:BB:BB:BB

# 清空 ARP 缓存
ip neigh flush all
```

### 6.4 ARP 报文格式

```
┌──────────┬──────────┬────────────────┬────────────────┬─────────┐
│ 硬件类型 │ 协议类型 │ 硬件地址长度  │ 协议地址长度 │ OP    │
│ 2B      │ 2B      │ 1B            │ 1B           │ 2B    │
│ = 0x0001│ = 0x0800│ = 6 (MAC)     │ = 4 (IPv4)    │ 1=Req  │
└──────────┴──────────┴────────────────┴────────────────┴─────────┘
┌──────────────────────┬──────────────────────┬──────────────────┐
│ 发送方 MAC            │ 发送方 IP            │ 目标 MAC          │
│ 6B                   │ 4B                  │ 6B              │
└──────────────────────┴──────────────────────┴──────────────────┘
┌────────────────┐
│ 目标 IP         │
│ 4B             │
└────────────────┘
```

### 6.5 ARP 类型

| 类型 | OP 码 | 用途 |
|---|---|---|
| ARP 请求 | 1 | "谁是 X.X.X.X？"（广播） |
| ARP 响应 | 2 | "我是！MAC = xx:xx:xx:xx:xx:xx"（单播） |
| RARP 请求 | 3 | MAC → IP |
| RARP 响应 | 4 | |
| **免费 ARP**（Gratuitous） | 1 | 自报家门（探测 IP 冲突） |

### 6.6 ARP 欺骗（攻击）

**原理**：发送伪造的 ARP 响应，把别人 IP 的 MAC 改成攻击者 MAC，**流量被劫持**。

```
正常：   192.168.1.1 = 路由器MAC（CC:CC:CC:CC:CC:CC）
被欺骗： 192.168.1.1 = 攻击者MAC（DD:DD:DD:DD:DD:DD）
         ↓
所有发到网关的流量 → 经过攻击者 → 再到网关（中间人攻击）
```

**防护**：交换机**端口绑定 MAC**（静态 ARP），或用 ARP 防火墙。

### 6.7 IPv6 替代品：NDP

IPv6 不再用 ARP（因为 IPv6 用组播 + 邻居发现协议 **NDP**）。

## §7 交换机原理（PDF 06）

### 7.1 交换机是 Layer 2 设备

**工作原理**：靠 **MAC 地址表**（MAC address table / CAM table）转发。

### 7.2 MAC 地址表

存储格式：`接口 ↔ MAC`

```
交换机内部表：

端口 1 ← AA:AA:AA:AA:AA:AA (PC1)
端口 2 ← BB:BB:BB:BB:BB:BB (PC2)
端口 3 ← CC:CC:CC:CC:CC:CC (PC3)
```

### 7.3 交换机 3 大动作

| 动作 | 触发 | 行为 |
|---|---|---|
| **学习**（Learning） | 收到任何帧 | 记下"源 MAC + 入端口"到 MAC 表 |
| **转发**（Forwarding） | 已知目标 | 从**对应端口**发出 |
| **泛洪**（Flooding） | 未知目标 / 广播 | 从**所有端口**发出（除入端口外） |

### 7.4 转发流程图

```
PC1 → SW（帧目标 MAC = BB:BB:BB:BB:BB:BB）
  ↓
SW 查 MAC 表
  ├─ 表里有 → 只从 BB 端口转发（学习/转发）
  ├─ 表里无 → 从所有端口泛洪（除入端口）
  └─ 目标 MAC = FF:FF:FF:FF:FF:FF → 全部端口（广播）

PC1 → SW（帧源 MAC = AA:AA:AA:AA:AA:AA）
  ↓
SW 学习：AA=端口1（更新 MAC 表）
```

### 7.5 广播域 vs 冲突域

| 概念 | 范围 | 隔离设备 |
|---|---|---|
| **冲突域** | 同网段内可能冲突的设备 | **交换机每个端口一个域** |
| **广播域** | 接收同一广播的设备集合 | **路由器/ VLAN 隔离** |

```
冲突域（交换机每个端口独立）：          广播域（路由器隔离）：
[PC1]---[P1]                        [PC1]---[P1]
[PC2]---[P2]---[SW]                 [PC2]---[P2]---[SW1]---[R1]----[SW2]---[PC3]
[PC3]---[P3]                        [PC3]---[P3]
隔离✓ 每个端口独立                    隔离✗ 路由器前面是同一广播域
                                     隔离✓ 路由器左右是 2 个广播域
```

### 7.6 交换机的 2 大类型

| 类型 | 特点 |
|---|---|
| **未管理交换机**（傻） | 接上就能用，不能配置 |
| **可管理交换机** | 可配置 VLAN / 端口 / 镜像 / ACL |

### 7.7 关键命令（华为交换机）

```bash
display mac-address              # 看 MAC 地址表
display mac-address aging-time   # 看老化时间（默认 300s）
display interface brief          # 看端口状态
```

### 7.8 交换机 vs 路由器对比

| 维度 | 交换机 | 路由器 |
|---|---|---|
| 工作层 | Layer 2 | Layer 3 |
| 关键表 | **MAC 地址表** | **路由表** |
| 关键标识 | MAC 地址 | IP 地址 |
| 隔离广播域 | ❌（除非 VLAN） | ✅ |
| 速度 | 快（硬件转发） | 稍慢（路由计算） |

### 易错点

- ❌ 交换机包打所有端口 → **默认是泛洪**（学习期），不是"包打所有"
- ❌ 一个交换机隔离广播域 → 只能隔离**冲突域**（除非 VLAN）
- ❌ 交换机看 IP → 交换机看 **MAC**（Layer 2）

## §8 易错点 ×10

1. **OSI 模型是实际协议栈** → OSI 是**理论**，实际是 TCP/IP 4 层
2. **MAC 全球唯一** → 实际**可能重复**（伪造/OUI 不规范）
3. **私有 IP 直接连公网** → 私有 IP 需 NAT 转换才能上公网
4. **子网掩码决定主机数**（不是网络号位数） → 是 **2^(32-网络位数) - 2**
5. **忘了网络号/广播不可用** → 实际可用 IP 是中间段
6. **IPv6 也有广播** → IPv6 **没有广播**，全部用组播
7. **CSMA/CD 现在还要用** → 全双工时代已不需要
8. **ARP 跨网段工作** → ARP **只在同一广播域**工作（跨网段用代理 ARP 或网关）
9. **路由器只用 IP** → 现代路由器是**多层设备**（NAT/防火墙/VPN）
10. **MAC = IP** → MAC 在 Layer 2，IP 在 Layer 3，**层级化分工**

## §10 面试 6 大追问

1. **OSI 7 层 vs TCP/IP 4 层的对应关系？**
   - TCP/IP 应用层 = OSI 5+6+7（会话 + 表示 + 应用）
   - TCP/IP 传输层 = OSI 4
   - TCP/IP 网络层 = OSI 3
   - TCP/IP 网络接口层 = OSI 1+2（物理 + 链路）
   - **OSI 是理论，TCP/IP 是实际**

2. **IPv4 地址 192.168.1.100/26，网络号 + 可用主机范围 + 广播？**
   - /26 = 255.255.255.192 = 网络号 26 位
   - 子网步长 = 256 - 192 = 64
   - 落入子网：192.168.1.64/26
   - **网络号：192.168.1.64**
   - **可用主机：192.168.1.65 ~ 192.168.1.126**
   - **广播地址：192.168.1.127**

3. **ARP 工作的核心原理是什么？会广播吗？**
   - **ARP 是数据链路层协议**，在**同一广播域**内工作
   - ARP 请求是**广播**（FF:FF:FF:FF:FF:FF）
   - ARP 响应是**单播**（直接回给请求方）
   - ARP **不能跨网段**（跨网段要找网关）

4. **交换机和路由器的本质区别？**
   - 交换机看 **MAC** 工作（Layer 2）
   - 路由器看 **IP** 工作（Layer 3）
   - 交换机每个端口独立冲突域
   - 路由器每个接口独立广播域
   - 路由器能隔离广播，交换机不能（除非 VLAN）

5. **MAC 是 IP 的另一种说法吗？**
   - **不是**。MAC 是 Layer 2（网卡烧录、固定），IP 是 Layer 3（按网络划分、可变）
   - MAC 标识"我是谁"，IP 标识"我在哪"
   - ARP 完成 IP → MAC 的解析

6. **IPv6 比 IPv4 强在哪？**
   - 地址空间更大（2^128 vs 2^32）
   - 头部固定（40 字节），路由器处理更快
   - **无状态自动配置**（无需 DHCP）
   - 原生 **IPSec**（IPv4 是额外加）
   - **没有广播**，全用组播（效率更高）
