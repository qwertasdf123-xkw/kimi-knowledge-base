## §0. 心智模型：路径 = GPS 导航路线

> 把文件系统想成一座城市，理解路径就更直观。

| 路径概念 | GPS 比喻 | 说明 |
|---|---|---|
| **绝对路径**（`/a/b/c`） | 输入"完整地址"，从**市中心（根）** 出发 | 不论你在哪，都能到达 |
| **相对路径**（`a/b`） | 输入"附近地标"，从**当前位置**出发 | 省事，但依赖出发点 |
| **`.`** | "我所在的这个路口" | 当前目录的简写 |
| **`..`** | "上一条街道" | 父目录的简写 |
| **`~`** | "我的家" | 当前用户的 `$HOME` |
| **`~user`** | "别人家"（需认识） | 指定用户的 `$HOME` |
| **`-`** | "上一个去过的地方" | shell 的 `$OLDPWD` |
| **`pwd`** | "我现在的位置" | 当前工作目录 |

> **核心口诀**：**绝对路径给"地址"，相对路径给"方向"。**

### 为什么"路径"是个值得理解的概念？

- 命令行几乎所有操作都需要"找到某个文件"。
- "如何描述这个文件的位置" = 路径。
- 如果路径理解错了，`cd`、`cp`、`rm` 都可能往错的地方去——**最常见的事故源**。

## §1. 三种路径形式

### 1.1 绝对路径（absolute path）

```bash
cd /etc/nginx
cat /var/log/syslog
ls /usr/local/bin
```

- **必以 `/` 开头**——根目录是唯一起点。
- 不依赖当前位置。
- **脚本推荐**——可移植、可重复。
- **缺点**：长，难读。

### 1.2 相对路径（relative path）

```bash
# 当前在 /srv/project，下面演示相对路径
cd src/main           # 进 src/main 目录
cd ../docs            # 进上一级的 docs 目录
cat ./README.md       # 当前目录的 README.md
cat ../README.md      # 上一级的 README.md
cat ../../etc/nginx/nginx.conf  # 上一级的上一级的 etc/nginx/nginx.conf
```

- **不以 `/` 开头**——以当前目录为基准。
- 短、好读。
- **缺点**：依赖当前位置，易错。

### 1.3 特殊路径：`.` 和 `..`（最反直觉的两个符号）

| 符号 | 含义 | 物理存在 | 备注 |
|---|---|---|---|
| `.` | 当前目录 | ✅ 每个目录都有 | inode 是 `dirent` 的特殊项 |
| `..` | 父目录 | ✅ 每个目录都有 | inode 是 `dirent` 的特殊项 |

**关键事实**：

1. `.` 和 `..` 是**真实的硬链接**——它们占据父目录的 dentry 槽位。
2. `..` 在根目录下仍然存在，但指向**自己**（根目录没有"父"）。
3. `cd .` 是 no-op（不切走）。
4. `cd ..` 切到父目录——这跟符号链接 + 软链解析有关（见 [[Linux目录导航]] 的 `-L`/`-P` 行为）。

**演练**：

```bash
$ pwd
/srv/project
$ cd .
$ pwd
/srv/project                    # 哪儿也没去
$ cd ..
$ pwd
/srv                            # 上一级
$ cd ../..
$ pwd
/                                # 再上一级（根）
```

### 1.4 路径简写速查表

| 写法 | 含义 | POSIX 标准？ |
|---|---|---|
| `/path` | 绝对路径 | ✅ |
| `path` 或 `./path` | 相对路径 | ✅ |
| `./` 或 `.` | 当前目录 | ✅ |
| `../` 或 `..` | 父目录 | ✅ |
| `~` | 当前用户 `$HOME` | bash 扩展 |
| `~user` | 指定用户 `$HOME` | bash 扩展 |
| `~+` / `~-` | dirs 栈顶 / 次顶 | bash 扩展 |
| `-` | `$OLDPWD` | ✅ |
| （空参数给 `cd`） | 切到 `$HOME` | ✅ |

> **bash 特性 vs POSIX**：`~+` `~-` `~user` 是 bash 扩展，写跨 shell 脚本别用。

### 1.5 实战：路径的常见事故与规避

**事故 1：相对路径在脚本里"鬼打墙"**

```bash
# 错误：在 crontab 里这样写
cd /srv/app
rm -rf ./tmp/*      # ./tmp 相对当前脚本所在目录
# 但 cron 的 cwd 是 $HOME，可能删错地方！
```

```bash
# 正确：用绝对路径
cd /srv/app && rm -rf /srv/app/tmp/*
```

**事故 2：`cd ..` 跳错地方（符号链接穿越）**

```bash
$ mkdir -p /tmp/real/dir
$ ln -s /tmp/real/dir /tmp/link
$ cd /tmp/link && cd ..
$ pwd                 # /tmp（基于逻辑 PWD）
$ pwd -P              # /tmp/real（基于物理 PWD）
# 解决方法：cd -P ... 切物理路径
```

**事故 3：路径含空格没加引号**

```bash
$ cd My Documents
bash: cd: My: No such file or directory      # 拆成两个参数
$ cd "My Documents"                          # 必须加引号
```

## §2. 隐藏文件 / 目录

### 2.1 规则

> **以 `.` 开头的文件 / 目录就是隐藏。**

```bash
$ ls       # 默认不显示隐藏
$ ls -a    # 显示所有（包括 . 和 ..）
$ ls -A    # 显示所有（不含 . 和 ..）—— 推荐日常用

$ mkdir .ssh          # 创建隐藏目录
$ touch .env          # 创建隐藏文件
```

### 2.2 典型隐藏配置

| 路径 | 作用 |
|---|---|
| `~/.bashrc` | bash 交互启动 |
| `~/.bash_profile` | bash 登录启动 |
| `~/.profile` | sh 系登录启动 |
| `~/.ssh/` | SSH 密钥 + 配置 |
| `~/.ssh/authorized_keys` | SSH 公钥 |
| `~/.ssh/config` | SSH 客户端配置 |
| `~/.gitconfig` | git 全局配置 |
| `~/.ssh/known_hosts` | 已信任主机 |
| `~/.local/` | 用户级应用数据（XDG） |
| `~/.config/` | 用户级配置（XDG） |
| `~/.cache/` | 用户级缓存（XDG） |
| `~/.history` / `~/.bash_history` | 命令历史 |
| `~/.vimrc` | vim 配置 |
| `~/.gnupg/` | GPG 密钥环 |

### 2.3 路径里的"特殊隐藏"

| 路径 | 含义 |
|---|---|
| `.` | 当前目录 |
| `..` | 父目录 |
| `...` | **没有这个**（不是祖辈，是普通文件） |
| `~-` / `~+` | dirs 栈（bash 扩展） |

> **反直觉点**：`...` 就是普通文件 `...`，不是祖辈目录。祖辈 = 多个 `../`。

## §3. FHS（Filesystem Hierarchy Standard）速查

> FHS 是 Linux 目录结构的"事实标准"。**2/3 主流发行版遵循**。

### 3.1 FHS 核心原则

1. **可共享 vs 不可共享**：`/usr` 可在多机共享，`/etc` 不行（机器相关）。
2. **静态 vs 可变**：`/usr` 静态（安装后不变），`/var` 可变（运行时变化）。
3. **FHS 3.0（2015）** 是当前最新版本。

### 3.2 FHS 目录分类

| 类别 | 目录 | 特性 |
|---|---|---|
| **必须可分享** | `/usr`, `/opt`, `/mnt`, `/srv`, `/tmp` | 可 NFS 共享 |
| **必须可分享 + 静态** | `/usr` | 装包不变 |
| **必须可分享 + 可变** | `/var`, `/tmp` | 运行时变 |
| **不可分享 + 静态** | `/etc`, `/boot` | 本机独享 |
| **不可分享 + 可变** | `/var`, `/run` | 本机的运行时 |
| **虚拟** | `/proc`, `/sys`, `/dev` | 内核接口，不占磁盘 |

### 3.3 FHS 速查

| 目录 | 内容 | 运维重点 |
|---|---|---|
| `/bin` | 用户命令（部分发行版已并入 `/usr/bin`） | 别手动改 |
| `/sbin` | 管理命令（同上，部分发行版并入 `/usr/sbin`） | 仅 root |
| `/lib` `/lib64` | 库（同样可能并入 `/usr/lib`） | 别动 |
| `/boot` | 内核 + 启动加载器 | 别动，独立分区 |
| `/etc` | 配置文件 | 编辑前先备份 |
| `/home` | 用户家目录 | 可独立分区，备份 |
| `/root` | root 家目录 | 不在 `/home` 是历史原因 |
| `/usr` | 用户级程序 + 库 + 文档 | 包管理器管理的在这里 |
| `/usr/local` | 手动编译的软件 | 不被包管理器覆盖 |
| `/opt` | 第三方独立软件 | 大型商业软件 |
| `/srv` | 服务数据 | 部分发行版不用 |
| `/var` | 可变数据（日志、缓存、临时队列、spool） | 易满，要监控 |
| `/var/log` | 日志 | logrotate |
| `/var/lib` | 应用状态（如 mysql 数据） | 备份重要 |
| `/var/cache` | 缓存 | 可清理 |
| `/var/spool` | 队列（mail、cron、print） | 监控堆积 |
| `/var/run` → `/run` | 运行时数据（PID 文件） | tmpfs，重启清空 |
| `/var/lock` → `/run/lock` | 锁文件 | tmpfs |
| `/tmp` | 临时文件 | 重启清空（tmpfs） |
| `/mnt` | 临时挂载点 | 老传统 |
| `/media` | 自动挂载（CD、USB） | udev 管理 |
| `/dev` | 设备文件 | udev / devtmpfs |
| `/dev/shm` | 共享内存（tmpfs） | 性能敏感场景 |
| `/proc` | 进程 / 系统信息 | 内核接口 |
| `/sys` | 内核对象 | 设备驱动 |
| `/run` | 运行时数据 | tmpfs |

### 3.4 现代分布："合并 `/usr`" 趋势

> **usrmerge**——很多现代发行版把 `/bin` → `/usr/bin`，`/sbin` → `/usr/sbin`，`/lib` → `/usr/lib`，etc.

- **Fedora 17+、Ubuntu 19+、Debian 12+** 已默认合并
- **RHEL 9** 已合并
- **原因**：符号链接地狱的简化 + systemd 推动
- **影响**：`/bin/sh` 现在是 `/usr/bin/sh` 的软链

```bash
# 看你的系统是否合并
ls -ld /bin /sbin /lib /lib64
# 如果显示 -> 链接关系，就是已合并
```

## §4. 三大发行版目录差异

### 4.1 RHEL / CentOS / Fedora

| 目录 | 特点 |
|---|---|
| `/etc/sysconfig/` | 旧的系统配置目录（含 network-scripts 等） |
| `/etc/yum.repos.d/` | yum/dnf 仓库配置 |
| `/etc/selinux/` | SELinux 配置 |
| `/var/log/messages` | 系统综合日志 |
| `/var/log/secure` | 安全日志（SSH 等） |
| `/etc/rc.d/rc.local` | 旧启动脚本入口（systemd 化后多被忽略） |
| `/var/log/cron` | cron 日志 |

### 4.2 Debian / Ubuntu

| 目录 | 特点 |
|---|---|
| `/etc/apt/sources.list` | apt 源 |
| `/etc/network/interfaces` | 老派网络配置（Ubuntu 18+ 改 netplan） |
| `/etc/NetworkManager/` | 桌面系统网络管理 |
| `/var/log/syslog` | 系统综合日志（Debian 风格） |
| `/var/log/auth.log` | 认证日志 |
| `/var/log/kern.log` | 内核日志 |
| `/etc/default/` | 服务默认配置（grub、keyboard 等） |
| `/var/cache/apt/archives/` | 下载的 deb 包缓存 |

### 4.3 Arch / Manjaro

| 目录 | 特点 |
|---|---|
| `/etc/pacman.conf` | pacman 配置 |
| `/etc/pacman.d/mirrorlist` | 镜像源 |
| `/var/log/pacman.log` | pacman 操作日志 |
| `/var/lib/pacman/` | pacman 数据库 |
| `/etc/X11/xorg.conf.d/` | X11 配置（仍在用） |

### 4.4 通用：发行版"中性"的目录

```bash
# 任何发行版都应遵守（POSIX FHS）
/etc/passwd
/etc/shadow
/etc/group
/etc/fstab
/etc/hosts
/etc/resolv.conf
/etc/nsswitch.conf
```

## §5. 目录的运维实战

### 5.1 看各目录占多大

```bash
# 看分区（不展开）
df -h

# 看具体目录占空间
du -sh /var/log
du -sh /var/log/*

# 找出 N 个最大的
du -h / | sort -h | tail -20

# 看 inode 使用
df -i
```

### 5.2 看挂载点

```bash
mount                  # 看当前挂载
findmnt                # 树形展示
findmnt /var           # 看 /var 在哪个挂载点
lsblk                  # 看块设备
cat /proc/mounts       # 内核视图
```

### 5.3 看进程打开的文件

```bash
lsof /var/log/syslog   # 谁打开了 syslog
fuser -v /var/log      # 同上
fuser -k /var/log      # 强制结束（慎用）

# 用 /proc 看进程的 fd
ls -l /proc/$(pidof nginx)/fd
```

### 5.4 看磁盘满了怎么办

```bash
# 1) 看是哪里满的
df -h
du -sh /* 

# 2) 常见清空目标
journalctl --vacuum-time=7d           # systemd 日志
apt clean                            # apt 缓存 (Debian)
yum clean all                        # yum 缓存 (RHEL)
find /tmp -type f -atime +30 -delete # 老 tmp 文件
find /var/log -name "*.gz" -mtime +30 -delete  # 老归档日志

# 3) 大文件找法
find / -size +500M -type f 2>/dev/null
du -h / | sort -h | tail -30
```

### 5.5 紧急：磁盘 100% 满了怎么救

```bash
# 1) 先看哪些目录能临时清理
df -h
du -sh /var/log/* 

# 2) 临时腾空间：清掉 /var/log/老归档
> /var/log/syslog      # 注意：截断不等于删
rm /var/log/syslog.*.gz  # 删归档

# 3) 增容（视情况）
lvextend -L +10G /dev/vg/root
resize2fs /dev/vg/root

# 4) 漂移（lvm）
pvmove ...
```

## §6. 面试 5 大追问

### Q1：`.` 和 `..` 是真实的文件吗？

**答案**：**是真实的目录条目**。每个目录都至少有 `.` 和 `..` 两个 dentry。

**加分话术**：
> "面试提到这个，我可以继续说：`..` 在根目录里指向自己，因为根目录没有父。但跨设备时，`..` 会进入父目录对应的挂载点——这是 mount tree 的细节。"

### Q2：硬链接可以指向目录吗？为什么 `..` 算"特殊"？

**答案**：**普通用户不能创建指向目录的硬链接**（除了 `.` 和 `..`，内核会强制）。
- 原因：避免目录环（如果 `a` 硬链 `b`，`b` 硬链 `a`，会循环）。
- `.` 和 `..` 是内核特殊"创建"的，不受此限。
- root 可以创建目录硬链，但有限制（`protected_hardlinks`）。

**加分话术**：
> "Linux 4.x 之前的 syscall `link(2)` 实际上允许 root 创建目录硬链（`rename(2)` 内部就用它重命名目录）。但 `ln` 命令前端不让做，是为了预防 cycle。"

### Q3：绝对路径和相对路径哪个长好？脚本里用哪个？

**答案**：**脚本里绝对路径**——可移植、可重复。
- 相对路径短，但依赖运行时的 cwd。
- 写 cron / systemd 单元 / CI 脚本时一定用绝对。

**加分话术**：
> "我会区分：交互 shell 用相对路径省事；脚本、自动化、配置一律绝对路径。"

### Q4：FHS 是必须遵守的吗？违反会怎样？

**答案**：**FHS 是建议不是强制**——Linux 基金会维护，发行版选择遵守。
- 违反后果：第三方软件可能找不到文件；包管理器可能装错地方。
- `/opt`、`/usr/local` 是"逃逸口"——你装非标准东西可以放这里。

**加分话术**：
> "FHS 3.0（2015）是当前标准。RHEL、Debian、Ubuntu、SUSE 都遵守，但 Arch、Slackware 有自己的扩展。一些嵌入式 Linux 会做大量精简。"

### Q5：`/tmp` 和 `/var/tmp` 的区别？

**答案**：

| 目录 | 挂载 | 重启清空？ | 用途 |
|---|---|---|---|
| `/tmp` | 通常 tmpfs | ✅ | 短生命周期的临时文件 |
| `/var/tmp` | 通常在磁盘分区 | ❌ | 长生命周期的临时文件 |

**加分话术**：
> "systemd-tmpfiles 定期清理 `/tmp`（默认 10 天），但不碰 `/var/tmp`。所以重要临时文件（如编译中间结果）应该放 `/var/tmp`，避免被清掉。"

## §7. 易错点 ×10

1. **`cd .` 不切走**——这是个 no-op。
2. **`...` 不是祖辈目录**——就是普通文件 `...`。
3. **相对路径在脚本里最容易翻车**——cron 的 cwd 可能是 `$HOME`，不是你的脚本目录。
4. **`/tmp` 重启清空**——别把重要文件放这里。
5. **`cd ..` 在符号链接下会跳到"父"的链接目录而非物理父**——用 `cd -P`。
6. **`~user` 是 bash 扩展**——POSIX shell 不支持，写脚本别用。
7. **隐藏文件不一定真的"重要"**——只是约定，但 `ls` 不显示而已（`ls -a` 全暴露）。
8. **FHS 推荐 ≠ 强制**——某些发行版（如 LFS、Alpine）会自己改。
9. **`/etc` 不应被 NFS 共享**——机器相关配置。
10. **`/usr` 可被 NFS 共享（只读）**——这就是早期无盘工作站的基础。
