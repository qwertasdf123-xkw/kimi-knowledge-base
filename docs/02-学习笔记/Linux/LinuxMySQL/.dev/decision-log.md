# Decision Log

## D-001：形态采用 OpenStack 模板

**Reason**：用户选择"教材全覆盖 + OpenStack 形态"，对齐 vault 第 32 个模块 OpenStack 的结构（7 分章节 + 主笔记 + canvas + 镜像），保持 vault 模块风格一致性。

**Alternatives**：
- 单文件形态（像 Redis 3113 行）→ 教材 196 页拆入单文件会过长（>5000 行），不利于分章节导航
- 实操导向（运维手册）→ 跳过理论，覆盖不全

**Supersedes**: 无

## D-002：分章节拆为 8 个笔记（00~08）

**Reason**：PDF 7 一级章节 + 00 学习路线 = 8 个分章节。SQL 语言（ch3）跨度 101 页（44%~73%），按主题拆为 03/04/05 三章避免单文件过大。

**Alternatives**：
- 严格按 PDF 7 章 → ch3 单独成文会达 ~3000 行，超出 L1 单文件合理范围
- 更细拆（10+ 章）→ 增加模块碎片化，跨章节引用成本高

**Supersedes**: 无
