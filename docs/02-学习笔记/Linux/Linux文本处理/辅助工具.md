# Linux 文本处理辅助工具速查：cut / tr / sort / uniq / wc / xargs

> 本文是 **Linux文本处理 模块的"工具箱补完"**——配合 [[grep]] / [[sed]] / [[awk]] / [[输入输出重定向]] 形成完整流水线。这 6 个工具都是**单功能小命令**，但**组合起来威力巨大**。
>
> **核心定位**：
> - `cut` — **按列切**（固定分隔符）
> - `tr` — **按字符替换 / 删除**
> - `sort` — **排序**（默认字典序，-n 数字，-r 反序）
> - `uniq` — **去重**（只能去相邻的重复行）
> - `wc` — **统计**（行/字节/字符）
> - `xargs` — **构造参数**（从 stdin 给命令造 argv）
>
> **链路呼应**：
> - → [[grep]]：grep 找行 → cut/tr 切字段 → sort/uniq/wc 统计
> - → [[sed]]：sed 改行 → sort/uniq 排序去重
> - → [[awk]]：awk 切字段（更强）→ 这些是"轻量替代"
> - → [[输入输出重定向]]：xargs 是管道的"argv 适配器"
> - → [[linux文件查询]]：`wc -l` 数行、`xargs` 配合 `find` 是经典组合
> - → [[目录的权限]]：管道与 xargs 的权限模型
>
> 备注：编写时网络访问受限，所有结论以本地 man 手册语义为准。

## §0. 心智模型：六个小工具 = 一条流水线

> 这 6 个工具**每个只做一件事**。把它们想成流水线上的**单功能工位**。

```
原始文本
   │
   ▼
[grep]  ←─ 过滤行（前面三件套之一）
   │
   ▼
[cut / tr]  ←─ 切列 / 改字符（轻量处理）
   │
   ▼
[sort]  ←─ 排序（让重复相邻）
   │
   ▼
[uniq]  ←─ 去重（只对相邻生效）
   │
   ▼
[wc]  ←─ 计数（行/字/字节）
   │
   ▼
[xargs]  ←─ 把结果"塞"给下一个命令的参数
```

> **核心口诀**：**"找 → 切 → 排 → 去 → 数 → 传"**——这是文本处理的标准流水线。

### 何时用这些小工具 vs awk？

| 场景 | 用 cut/tr/sort/uniq/wc | 用 awk |
|---|---|---|
| 固定分隔符切列 | ✅ cut | ✅ $1,$2 |
| **多分隔符**（含空格+tab） | ❌ 难 | ✅ awk |
| 简单字符替换 | ✅ tr | ✅ gsub |
| 排序+去重 | ✅ sort -u | 需写 |
| 性能（大数据） | ✅ 极快（专用算法） | 略慢 |
| 多条件复杂处理 | ❌ | ✅ |

> **实战原则**：**简单场景用 cut/tr/sort/uniq（快）**；**复杂场景用 awk（强）**。

## §1. `cut` —— 按列切

### 1.1 三种切法

| 模式              | 语法            | 用途            | 示例                        |
| --------------- | ------------- | ------------- | ------------------------- |
| **按字段**         | `cut -f N`    | TAB 分隔，取第 N 列 | `cut -f1 file`            |
| **按字段（自定义分隔符）** | `cut -d: -fN` | 任意分隔符         | `cut -d: -f1 /etc/passwd` |
| **按字符位置**       | `cut -c N-M`  | 取第 N-M 个字符    | `cut -c1-5 file`          |

### 1.2 实战

```bash
# 取 /etc/passwd 的用户名（冒号分隔，第 1 列）
cut -d: -f1 /etc/passwd

# 取多列
cut -d: -f1,3 /etc/passwd          # 用户名 + UID
cut -d: -f1-3 /etc/passwd          # 用户名 + UID + GID

# 按字符位置取（前 10 个字符）
cut -c1-10 file

# 输出分隔符（--output-delimiter）
cut -d: -f1,3 --output-delimiter=' | ' /etc/passwd
# 之前默认分隔符是输入分隔符，加这个能改

# 反选（除了某列都要）
cut -d: -f1 --complement /etc/passwd
# 输出除了第 1 列的所有列
```

### 1.3 经典陷阱

```bash
# cut 默认分隔符是 TAB，不是空格！
echo "a b c" | cut -f2
# 输出空（因为没有 tab 分隔）

# 必须显式指定
echo "a b c" | cut -d' ' -f2
# 输出 "b"
```

### 1.4 vs awk

```bash
# cut 能干的 awk 都能干
cut -d: -f1 /etc/passwd
awk -F: '{print $1}' /etc/passwd     # 等价

# 复杂分隔（多个空格、混合 tab）
awk '{print $1}' file                # 自动合并空白
cut -f1 file                         # 默认要求严格 TAB
```

## §2. `tr` —— 字符转换 / 删除

### 2.1 核心用法

```bash
# 转换（小写 → 大写）
echo "hello" | tr 'a-z' 'A-Z'
# 输出：HELLO

# 删除字符
echo "hello123" | tr -d '0-9'
# 输出：hello

# 压缩重复字符
echo "hello    world" | tr -s ' '
# 输出："hello world"（多个空格 → 1 个）

# 取补集（除指定字符外都删）
echo "hello world" | tr -cd 'a-z'
# 输出："helloworld"（只保留小写字母）

# 替换单个字符
echo "a:b:c" | tr ':' '\n'
# 输出三行：a / b / c（把冒号换成换行）
```

### 2.2 关键选项

| 选项   | 作用                | 示例                         |
| ---- | ----------------- | -------------------------- |
| `-d` | 删除字符集             | `tr -d '\r'`（删 Windows 换行） |
| `-s` | 压缩连续重复为单          | `tr -s ' '`                |
| `-c` | 取补集               | `tr -cd 'a-zA-Z'` 只保留字母    |
| `-t` | 截断 SET2 到 SET1 长度 | 极少用                        |

### 2.3 实战

```bash
# Windows → Unix 文件转换（删 \r）
tr -d '\r' < dos.txt > unix.txt

# 大小写互转
tr 'a-z' 'A-Z' < file               # 全部转大写
tr 'A-Z' 'a-z' < file               # 全部转小写

# 数字求和（一行所有数字相加，tr 把非数字变换行）
echo "1 2 3 4 5" | tr ' ' '\n' | paste -sd+ | bc
# 输出 15

# 把多个连续空格压缩为单个
tr -s ' ' < file                    # 比 sed 's/  */ /g' 更简洁

# 提取文件中的所有数字
tr -cd '0-9' < file                 # 只保留数字，其他全删

# 替换字符（一一对应）
echo "abc" | tr 'abc' 'xyz'
# 输出："xyz"
```

### 2.4 字符类（GNU 扩展）

```bash
# 用 [:class:] 字符类
tr '[:lower:]' '[:upper:]' < file    # 小写转大写
tr -d '[:punct:]' < file             # 删标点
tr -d '[:cntrl:]' < file             # 删控制字符
```

## §3. `sort` —— 排序

### 3.1 必背选项

| 选项 | 作用 | 默认 |
|---|---|---|
| `-n` | 按数字排序 | 默认字典序 |
| `-r` | 反向 | 升序 |
| `-k N` | 按第 N 列排序 | 全行 |
| `-t X` | 字段分隔符 X | 空白 |
| `-u` | 去重（= sort + uniq） | 保留重复 |
| `-f` | 忽略大小写 | 区分 |
| `-h` | 人类可读（K/M/G） | 字节 |
| `-V` | 版本号排序（1.10 > 1.2） | 字典序 |
| `-M` | 月份排序（Jan < Feb） | 字典序 |
| `-o file` | 输出到文件（可同输入） | stdout |
| `-s` | 稳定排序（同分保持原序） | 不保证 |

### 3.2 实战

```bash
# 默认字典序（坑！）
echo -e "10\n2\n100" | sort
# 输出：10 / 100 / 2

# 数字排序
echo -e "10\n2\n100" | sort -n
# 输出：2 / 10 / 100

# 反向数字
sort -rn file                       # 数字大→小

# 按第 3 列排序
sort -k3 file

# 多列：先按第 1 列，再按第 2 列
sort -k1,1 -k2,2 file

# 字段分隔符 + 数字
sort -t: -k3 -n /etc/passwd        # 按 UID 排序

# 按多个字段（复杂）
ls -l | sort -k5 -n -r             # 按文件大小（第 5 列）倒序

# 人类可读大小排序
du -sh * | sort -h -r               # 最大的在前

# 版本号排序
echo -e "v1.10\nv1.2\nv1.1" | sort -V
# 输出：v1.1 / v1.2 / v1.10（数字感知）

# 唯一性（去重）
sort -u file                        # 等价 sort | uniq

# 输出到文件（可同名）
sort file -o file                   # 原地排序（比 sort -o file 安全）
```

### 3.3 经典陷阱

```bash
# 字典序 vs 数字序
sort -k2 file                       # 字典序
sort -k2n file                      # 数字序
# 注意 -k2n 不是 -k2 -n（虽然结果一样）

# 排序范围
sort -k2,2 file                     # 只按第 2 列（精确范围）
sort -k2 file                       # 从第 2 列开始到行尾（粗范围）
# 这俩可能给出不同结果！
```

### 3.4 性能特性

- **`sort` 用外部排序**——可处理超大文件（远超内存），靠 tmpfile
- **LOCALE 影响**——`LC_ALL=C sort` 加速 2-10 倍（按字节排）

```bash
# 排序大文件加速
LC_ALL=C sort huge.txt > sorted.txt
```

## §4. `uniq` —— 去重（只看相邻）

### 4.1 核心要点

> **`uniq` 只能去相邻的重复行**——必须先 `sort`，否则无效！

```bash
# 错误：直接 uniq 去不掉
echo -e "a\nb\na" | uniq
# 输出：a / b / a（a 没去，因为不相邻）

# 正确：先 sort 再 uniq
echo -e "a\nb\na" | sort | uniq
# 输出：a / b（a 排到顶 + 重复相邻 → 去重）
```

### 4.2 必背选项

| 选项 | 作用 | 示例 |
|---|---|---|
| `-c` | 数每个值的出现次数 | `sort \| uniq -c` 数频次 |
| `-d` | 只显示重复的行 | 过滤出有重复的 |
| `-u` | 只显示唯一的行 | 过滤出无重复的 |
| `-i` | 忽略大小写 | - |
| `-f N` | 跳过前 N 字段比较 | - |
| `-s N` | 跳过前 N 字符比较 | - |
| `-w N` | 只比较前 N 字符 | - |

### 4.3 实战

```bash
# 数频次（TOP 10 IP 经典案例）
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head

# 只看有重复的行（可能有 bug 的数据）
sort file | uniq -d

# 只看无重复的行（每个都唯一）
sort file | uniq -u

# 大小写不敏感
sort -f file | uniq -i

# 只看前 N 个字符的去重
cat file | uniq -w 10
# 只看每行前 10 字符的去重
```

### 4.4 与 `sort -u` 对比

```bash
# sort -u：一遍完成（更快）
sort -u file

# sort + uniq：两遍（uniq -c 数频次时才用）
sort file | uniq -c
# → sort -u 做不到数频次！
```

**记忆口诀**：

> **"要去重用 sort -u，要数次数用 sort | uniq -c"**

## §5. `wc` —— 统计

### 5.1 三个核心数

```bash
wc file
# 输出：行 词 字节 文件名

wc -l file         # 行数
wc -w file         # 词数（按空格/TAB 分）
wc -c file         # 字节数
wc -m file         # 字符数（多字节字符不同）
wc -L file         # 最长行的长度
```

### 5.2 实战

```bash
# 数代码行数
find src -name "*.py" -exec cat {} \; | wc -l

# 数日志行数（最快）
wc -l access.log                   # 比 cat file | wc -l 少一个进程

# 多个文件
wc -l *.py
# 输出：  100 a.py  200 b.py  300 total

# 最长行长度（看 CSV 列数异常）
wc -L file.csv                      # 比其他行长得多的可能是脏数据

# 数匹配次数（经典）
grep -c "ERROR" log                 # 匹配行数
grep -o "ERROR" log | wc -l         # 匹配次数（多次匹配算多次）
```

### 5.3 与 awk 对比

```bash
# wc -l vs awk END
wc -l file                          # 只数行
awk 'END{print NR}' file            # 数 NR（多文件时是总数）

# 多文件
wc -l a b c                         # 输出每个 + total
awk 'END{print NR}' a b c           # 只输出总数
```

## §6. `xargs` —— 把 stdin 变成 argv

### 6.1 为什么需要 xargs？

```bash
# 很多命令不读 stdin，必须给"参数"
ls *.txt
# 等价：rm file1.txt file2.txt ...

# find + rm 的问题
find . -name "*.log" | rm            # ❌ rm 不读 stdin
find . -name "*.log" | xargs rm      # ✅ xargs 把 stdin 转成 rm 的参数
```

### 6.2 必背选项

| 选项 | 作用 | 示例 |
|---|---|---|
| `-n N` | 每 N 个参数调一次命令 | `xargs -n 1 echo` |
| `-I {}` | 用 `{}` 占位（可多次出现） | `xargs -I {} mv {} {}.bak` |
| `-0` | NUL 分隔（配合 `find -print0`） | 处理含空格/换行的文件名 |
| `-P N` | 并发 N 个进程 | `xargs -P 4 gzip` |
| `-r` | 没输入时不执行（GNU） | 避免空跑 |
| `-t` | 执行前打印命令 | 调试用 |
| `-p` | 每条询问 y/n | 交互 |

### 6.3 实战

```bash
# 删所有 .log
find . -name "*.log" -print0 | xargs -0 rm

# 批量重命名
find . -name "*.txt" -print0 | xargs -0 -I {} mv {} {}.bak

# 并发压缩（4 核）
find . -name "*.log" -print0 | xargs -0 -P 4 gzip

# 从文件读参数
xargs -a urls.txt curl -O

# 控制每批参数数
echo "1 2 3 4 5" | xargs -n 2 echo
# 输出：1 2 / 3 4 / 5

# 占位符
echo -e "a\nb\nc" | xargs -I {} echo "got: {}"
# 输出：got: a / got: b / got: c
```

### 6.4 关键陷阱

```bash
# 默认按空格/TAB 分隔，含空格的文件名会拆错
echo "my file.txt" | xargs rm
# 变成：rm my file.txt（两个文件！）

# 解决：find -print0 + xargs -0
find . -name "*.txt" -print0 | xargs -0 rm
```

## §7. 综合实战案例（10 个）

### 案例 1：TOP 10 IP

```bash
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head
# 拆分：awk 提取 IP → sort 排序 → uniq -c 数次数 → sort -rn 倒序 → head 前 10
```

### 案例 2：找两个文件的差异

```bash
# 按列取差异（只比较第 1 列）
cut -d: -f1 file1 | sort > /tmp/a
cut -d: -f1 file2 | sort > /tmp/b
diff /tmp/a /tmp/b
```

### 案例 3：批量解压

```bash
ls *.tar.gz | xargs -n 1 tar xzf
```

### 案例 4：清理重复行（保留第一次出现的）

```bash
# awk 的 !seen[] 实现
awk '!seen[$0]++' file
# 等价：sort -u（但保留原顺序）
```

### 案例 5：统计代码量

```bash
find src -name "*.py" -exec cat {} \; | wc -l
# 数所有 .py 文件总行数
```

### 案例 6：找最长行

```bash
awk '{print length, $0}' file | sort -rn | head -1
# 或：wc -L file（直接看长度）
```

### 案例 7：把多空格压成单空格

```bash
tr -s ' ' < file
# 比 sed 's/  */ /g' 简洁
```

### 案例 8：CSV → TSV

```bash
tr ',' '\t' < file.csv > file.tsv
```

### 案例 9：DOS → Unix 文件

```bash
tr -d '\r' < dos.txt > unix.txt
# 删 Windows 文件的 \r
```

### 案例 10：日志分析（统计 5xx 错误次数）

```bash
grep -oE "HTTP/1\.[01]\" [5][0-9]{2}" access.log | sort | uniq -c | sort -rn
# 提取所有 5xx 状态码 + 统计次数
```

## §8. 速查表

### 8.1 一行模式（one-liner）

```bash
# 数匹配次数
grep -o "ERROR" log | wc -l

# TOP 10
sort file | uniq -c | sort -rn | head

# 取第 N 列
cut -d: -f1 file

# 大小写转换
tr 'a-z' 'A-Z' < file

# 删 Windows 换行
tr -d '\r' < dos.txt > unix.txt

# 批量删除
find . -name "*.log" -print0 | xargs -0 rm

# 找唯一值
sort -u file

# 数行数
wc -l file

# 多空格压单空格
tr -s ' ' < file

# CSV 转 TSV
tr ',' '\t' < file.csv > file.tsv
```

### 8.2 决策树

```
要做什么？                    用什么？
─────────────────────────────────────────
按列切（简单分隔符）         → cut
按字符改 / 删              → tr
排序                       → sort
去重                       → sort -u（或 sort | uniq）
数次数                     → sort | uniq -c
数行 / 字节                 → wc
把 stdin 转成 argv          → xargs
─────────────────────────────────────────
字段复杂 / 多分隔符 / 多列   → awk（替代 cut/tr）
复杂统计                   → awk（替代 sort + uniq + wc）
```

## §9. 易错点 ×12

1. **`cut` 默认按 TAB，不是空格** —— `echo "a b" | cut -f2` 是空。要 `cut -d' ' -f2`。
2. **`uniq` 只能去相邻** —— 一定要先 `sort`！
3. **`sort` 默认字典序** —— "10" < "2"。要数字排序加 `-n`。
4. **`sort -k2` 是从第 2 列到行尾** —— 严格只按第 2 列用 `-k2,2`。
5. **`xargs` 默认按空格切** —— 文件名含空格必须 `-print0 | xargs -0`。
6. **`xargs` 没输入时**（GNU）默认不执行 —— `-r` 显式确认。
7. **`tr` 不支持正则** —— 只能用字符类 / 单字符。
8. **`wc -l` 数 `\n` 数** —— 文件无换行结尾会少 1。
9. **`sort -u` 和 `sort | uniq` 不同** —— `-u` 一遍完成，但**不能数频次**。
10. **`tr -d '\r'` 在 macOS 上不一样** —— BSD tr 不识别 `\r` 转义。
11. **`sort` 受 locale 影响** —— `LC_ALL=C sort` 加速明显。
12. **`cut -f` 不能选多字符分隔符** —— 只能 1 字符。要多字符用 awk。

## §10. 面试 8 大追问

### Q1：`cut` 和 `awk` 选谁？

**答案**：

| 场景 | cut | awk |
|---|---|---|
| 单字符分隔符 | ✅ 快 | ✅ |
| 多个分隔符（空格+tab） | ❌ | ✅ |
| 按字符位置 | ✅ `-c` | 复杂 |
| 大文件性能 | ✅（专用） | 略慢 |
| 字段计算（求和） | ❌ | ✅ |

**加分话术**：
> "我的经验：能 cut 就 cut（更快、语法更简单）。需要多分隔符、计算、复杂逻辑才换 awk。cut 性能接近 1.5x awk。"

### Q2：`sort -u` 和 `sort | uniq` 一样吗？

**答案**：

| 写法 | 性能 | 能否 `uniq -c` |
|---|---|---|
| `sort -u` | ✅ 更快（1 遍） | ❌ |
| `sort \| uniq` | 2 遍 | ✅ |
| `sort \| uniq -c` | 2 遍 + 数次数 | ✅ |

**加分话术**：
> "单纯去重用 `sort -u`；要数次数必须 `sort | uniq -c`。这是 awk 数 IP 频次的底层套路——awk 做不到 'sort -u' 一步到位。"

### Q3：`uniq` 不 sort 也能去重吗？

**答案**：**不能**。`uniq` 只能去**相邻**重复行。

```bash
echo -e "a\nb\na" | uniq
# 输出：a / b / a（a 没去，因为不相邻）

echo -e "a\nb\na" | sort | uniq
# 输出：a / b（先 sort 再 uniq 才去重）
```

**加分话术**：
> "uniq 的设计假设是'数据已经有序'——所以它做的是 O(n) 一次扫描，不维护 hash 表。如果数据无序，uniq 实际上是个'相邻压缩'工具。要真去重永远先 sort。"

### Q4：`xargs` 为什么要配合 `find -print0`？

**答案**：处理**含空格 / 换行 / 引号**的文件名。

```bash
# 错误：含空格的文件名被拆成两个
find . -name "*.txt" | xargs rm
# → rm "my" "file.txt"   ❌

# 正确：NUL 分隔（文件名不可能含 NUL）
find . -name "*.txt" -print0 | xargs -0 rm
# → rm "my file.txt"     ✅
```

**加分话术**：
> "NUL 字节（`\0`）是文件名唯一不能包含的字符（POSIX 规定）。所以 `-print0` + `-0` 是'安全通道'。99% 的生产脚本都用这对。"

### Q5：`tr` 和 `sed s/.../.../g` 区别？

**答案**：

| 场景 | tr | sed |
|---|---|---|
| 字符集替换 | ✅ `tr 'a-z' 'A-Z'` | 复杂 |
| 字符串替换 | ❌ 只能单字符 | ✅ `sed 's/foo/bar/g'` |
| 性能 | ✅（C 实现） | 略慢 |
| 正则 | ❌ | ✅ |

**加分话术**：
> "tr 是 sed 的'简化版'——只做字符级操作，但更快。大小写转换、删除特定字符用 tr；字符串替换、模式匹配用 sed。"

### Q6：`sort -k2` vs `sort -k2,2` 区别？

**答案**：

```bash
# sort -k2：从第 2 列到行尾整体作为 key
echo -e "b a\nb c\na b" | sort -k2
# 输出：b a（a 在第2列） / b c（c 在第2列） / a b（b 在第2列）
# 字典序：a < b < c

# sort -k2,2：只按第 2 列（忽略后续）
echo -e "b a\nb c\na b" | sort -k2,2
# 输出：b a / a b（按"a"和"b"，但只看第2列）
# b c 排哪里？按"c" → 最后
```

**加分话术**：
> "新手常踩的坑：`-k2` 是'从第 2 列开始'（含第 2 列之后的所有内容作 key），`-k2,2` 是'只第 2 列'。要严格只按某一列必须 `-kN,N`。"

### Q7：`wc -l` 一定准吗？

**答案**：**不一定**。

```bash
# 文件无换行结尾时少 1 行
printf "a\nb" | wc -l     # 输出 1（不是 2）
printf "a\nb\n" | wc -l   # 输出 2
```

**实战**：

```bash
# 严谨的数行（兼容无尾换行）
awk 'END{print NR}' file

# 或
grep -c "" file           # 数所有"空匹配"（每行 1 个）
```

**加分话术**：
> "生产日志经常没有尾换行（多个 cat 拼接、sed -i 操作可能引入）。`wc -l` 会少 1 行。要严谨用 `awk END{print NR}` 或 `grep -c ""`。"

### Q8：`xargs -I {}` 和 `-n 1` 区别？

**答案**：

| 写法 | 行为 | 用途 |
|---|---|---|
| `xargs -n 1 cmd` | 每 1 个参数调 1 次 cmd | 简单多调用 |
| `xargs -I {} cmd {} extra` | 每行替换 `{}` 占位 | 复杂处理 |
| `xargs -I {} cmd {}.bak` | 多次出现 `{}` 都替换 | 重命名类 |

```bash
# -n 1：每行调一次（参数追加）
echo -e "a\nb" | xargs -n 1 echo
# 输出：echo a → echo b

# -I {}：占位符可出现在多处
echo -e "a\nb" | xargs -I {} mv {} {}.bak
# 等价：mv a a.bak / mv b b.bak
```

**加分话术**：
> "-n 1 是'批量调用'，-I {} 是'模板替换'。要 mv/cp 这种'前后都用到文件名'的，必须 -I {}。日常批量重命名最常用。"
